추가 요청에 따라 1024px 이상 데스크톱 화면은 고정 헤더 아래 7개 전체 화면 슬라이드와 세로 스크롤 스냅을 사용합니다. 현장 사진과 지난 홍보 자료는 각각 한 슬라이드로 분리했습니다. 1440×900, 1280×720, 1024×600에서 각 슬라이드의 높이, 콘텐츠 잘림, 앵커 정렬과 한 번의 휠 스크롤 후 다음 슬라이드 정착을 확인했습니다. 768–1023px 태블릿은 연속 스크롤을 유지합니다.

각 데스크톱 슬라이드에는 현재 위치와 다음 내용을 표시하는 플로팅 CTA를 추가했습니다. 마지막 슬라이드에서는 행사 소개로 돌아가며, 문의 화면에는 제목이 포함된 이메일 문의 CTA를 둡니다. 정보 전달 중심이라는 기존 원칙에 따라 참여 회신이나 신청을 요구하지 않습니다. 1024×600에서도 CTA와 본문이 겹치지 않도록 별도의 짧은 화면 레이아웃을 적용했습니다.

### UX-02 작은 화면에서 날짜·장소가 첫 화면에 보이지 않음

- **위치:** [MobileExperience.tsx:291–328](../src/components/MobileExperience.tsx#L291), [mobile.css:17–36](../src/styles/mobile.css#L17)
- **현재:** 375×620(작은 아이폰의 카카오톡 인앱 브라우저 수준)에서 개요 영역은 388px에서 끝나고, 날짜·장소 카드는 393–474px에 있습니다. 카드 전체가 Peek 상태의 서랍 뒤로 숨습니다.
- **문제:** 행사에서 가장 중요한 정보가 첫 화면에 없습니다. 개요 영역은 스크롤할 수 있지만 `scrollbar-width: none`이라 스크롤할 수 있다는 단서도 없습니다.
- **수정안:** 서랍과 내비게이션 구조는 그대로 두고 개요 영역만 조정합니다. 날짜·시간·장소 카드를 히어로 제목 바로 아래로 올리고, 히어로 상단 여백(`padding-top: 47px`)과 행사명 `ST:talk`(58px) 크기를 작은 화면에서 줄입니다. 위원회 워드마크는 건드리지 않습니다.
- **완료 기준:** 375×620에서 스크롤 없이 날짜·시간·장소가 모두 보입니다.

### UX-05 지난 홍보물의 날짜가 이번 행사 날짜와 혼동됨

- **수정안:** 데스크톱 갤러리 설명에 모바일과 같은 안내 문구를 넣고, 홍보물 그룹 제목 옆에 "지난 행사 자료" 표시를 둡니다.
- **완료 기준:** 모바일과 데스크톱 모두 지난 홍보물 근처에 "이번 행사와 별개" 안내가 보입니다.

### PERF-01 페이지 안에서 원본 이미지 약 12MB를 그대로 사용

- **위치:** [assets/images/](../assets/images/), [gallery.ts](../src/data/gallery.ts), [DesktopLanding.tsx:191](../src/components/DesktopLanding.tsx#L191), [SheetContent.tsx](../src/components/SheetContent.tsx), [GalleryViewer.tsx](../src/components/GalleryViewer.tsx)
- **현재:**

  | 파일                               | 크기   | 해상도    |
  | ---------------------------------- | ------ | --------- |
  | sttalk-2026-spring-poster.jpg      | 7.0 MB | 5031×7087 |
  | sttalk-2025-table-talk.jpg         | 3.4 MB | 4032×3024 |
  | sttalk-2026-spring-banner.jpg      | 0.8 MB | 6000×1800 |
  | sttalk-2025-questions.jpg          | 0.6 MB | 2856×2142 |
  | sttalk-2025-table-conversation.jpg | 0.3 MB | 2016×1512 |

  페이지 안 이미지와 확대 보기가 같은 원본 파일을 씁니다. 데스크톱 첫 화면에서 3.4MB 히어로 사진을 바로 받고, 모바일 기록 탭을 열면 확대하지 않아도 포스터 7MB를 셀룰러로 받습니다.

- **수정안:**
  - 페이지 안에 표시하는 이미지(히어로, 갤러리 목록)만 800px·1600px 너비의 WebP(가능하면 AVIF 병행)로 만들어 `srcset`·`sizes`로 제공합니다.
  - 확대 보기는 원본 해상도를 유지하고, 확대 보기를 열었을 때만 불러옵니다. 포스터·책자처럼 작은 글씨가 있는 자료는 해상도를 제한하지 않습니다. 파일 크기를 줄이더라도 해상도는 그대로 두고 압축 품질만 조정합니다.
  - `gallery.ts`에 목록용 이미지와 확대용 원본 경로를 따로 둡니다.
  - 히어로 이미지는 `fetchpriority="high"`, 나머지는 `loading="lazy"`를 유지하고, `width`·`height`를 모든 `<img>`에 넣어 레이아웃 이동을 막습니다(데스크톱 갤러리 `<img>`에는 현재 없음).
- **완료 기준:** 첫 화면 이미지 전송량 400KB 이하. 확대 보기를 열기 전에는 원본 파일을 받지 않고, 확대 보기에서는 포스터의 작은 글씨가 원본과 같은 선명도로 보입니다.

### UX-03 서랍을 손잡이로만 조작할 수 있음

- **위치:** [MobileExperience.tsx:335–371](../src/components/MobileExperience.tsx#L335)
- **현재:** 드래그는 높이 44px 손잡이 버튼에서만 동작합니다. Peek 상태의 제목·요약 문장을 눌러도 반응이 없고, Half/Full에서 제목 영역이나 본문을 끌어 서랍을 내릴 수 없습니다.
- **문제:** 일반적인 앱 서랍(카드 어디든 끌기, 탭하면 펼침)과 달라 처음 보는 사용자가 서랍을 열거나 내리는 방법을 찾기 어렵습니다.
- **수정안:** 버튼을 추가하지 않고 기존 서랍의 조작 범위만 넓힙니다. 오른쪽 위 조작 버튼은 다시 넣지 않습니다.
  - Peek 상태에서 제목·요약 영역을 누르면 Half로 엽니다.
  - 서랍 제목 영역(`.sheet-heading`)도 손잡이와 같은 드래그 영역으로 씁니다.
  - 본문이 맨 위(`scrollTop === 0`)일 때 아래로 끌면 서랍이 한 단계 내려가도록 검토합니다. 본문 스크롤과 충돌하면 이 부분은 적용하지 않습니다.
- **완료 기준:** 손잡이 외에 Peek 카드와 제목 영역으로도 서랍을 열고 내릴 수 있고, 본문 스크롤은 기존처럼 동작합니다. 내비게이션의 Expanded/Compact 정책은 바뀌지 않습니다.

## 권장 작업 순서

1. **콘텐츠 정리:** C-01 → T-04 → C-03. 이후 작업이 한 곳의 데이터만 고치면 되도록 먼저 합칩니다.
2. **핵심 정보:** UX-02 → UX-05.
3. **성능:** PERF-01 → C-04.
4. **모바일 서랍 다듬기:** UX-03 → M-04 → M-05 → M-07.
5. **가독성:** UX-04 → T-01 → T-02 → T-03.
6. **데스크톱·반응형:** D-01 → D-02 → D-03 → R-01 → D-04~D-07.
7. **선택 제안:** 채택을 정한 항목만 수정 목록으로 옮겨 진행합니다.

각 단계가 끝나면 `npm run check`, `npm test`, `npm run format:check`, `npm run build`를 통과시키고, 375×620, 390×844, 690×900, 844×390, 1024×768, 1440×900에서 가로 넘침과 첫 화면 정보를 확인합니다. 모바일에서는 Peek·Half에서 Expanded, Full에서만 Compact가 유지되는지도 함께 확인합니다. 실제 iOS Safari·Android Chrome·카카오톡 인앱 브라우저 확인은 별도로 기록합니다.
